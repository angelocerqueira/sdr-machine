Smoke Test — Evolution → Webhook P2

Validar end-to-end o webhook receiver do WhatsApp Inbox antes de mergear PR #100.

Feature: feat/whatsapp-inbox-p2-webhook PR: #100 Foundation: PR #99 (P0-P1) já merged

Pré-requisitos

  • Evolution API rodando (Docker, VPS, ou serviço gerenciado)
  • Instance Evolution criada + conectada via QR (WhatsApp real funcionando)
  • Backend SDR rodando com variável SETTINGS_ENC_KEY setada (Fernet key)
  • URL pública do backend acessível pela Evolution (ngrok pra local, ou staging deploy)

Passos

1Subir backend local

docker compose up --build

Confirma que GET /api/health retorna {"status": "ok"}.

2Expor backend público

Local:

ngrok http 8000
# copia URL https://abc123.ngrok.io

Staging: usar Railway URL direto.

3Gerar HMAC secret + cadastrar Evolution

Gera secret:

openssl rand -hex 32
# ex: 9f2a8e1b...

Cadastra via PUT (assumindo session cookie válida ou bypass auth em dev):

curl -X PUT https://abc123.ngrok.io/api/workspace/integrations/evolution \
  -H "Content-Type: application/json" \
  -d '{
    "config": {
      "base_url": "https://evolution.seu-host.com",
      "instance": "nome-da-instance",
      "api_key": "EVOLUTION_API_KEY_AQUI",
      "webhook_secret": "9f2a8e1b..."
    }
  }'

Ou direto via SQL:

INSERT INTO integration_settings (workspace_id, provider, enabled, config)
VALUES (1, 'evolution', true,
  '{"base_url":"...", "instance":"...",
    "api_key":"<encrypted>", "webhook_secret":"<encrypted>"}');
Atenção: api_key e webhook_secret precisam estar cifrados via Fernet. Use encrypt() do módulo app.integrations.crypto: 
cd backend && venv/bin/python -c "
from app.integrations.crypto import encrypt
print(encrypt('SEU_VALOR_AQUI'))
"

4Configurar webhook na Evolution

URL do endpoint:

https://abc123.ngrok.io/api/webhooks/whatsapp/1/evolution

Na Evolution API (admin UI ou POST /webhook/set/<instance>):

  • URL: a do endpoint
  • Events: messages.upsert, messages.update
  • Header custom: X-Sdr-Signature com valor HMAC
Crítico: Evolution precisa enviar HMAC do raw body no header X-Sdr-Signature. Confirma na doc da Evolution se ela suporta isso nativamente. Se não, talvez precise de proxy intermediário ou desabilitar HMAC nesse smoke (skip secret, accept all — só pra teste, nunca em prod).

5Criar Lead com telefone real

INSERT INTO leads (nome, telefone, status)
VALUES ('Teste Smoke', '5544SEUNUMERO', 'outreach_sent');

Pega o id retornado.

(Opcional) OutreachMessage com provider_message_id pra testar status update:

INSERT INTO outreach_messages (lead_id, type, message_text, status, provider_message_id)
VALUES (<lead_id>, 'initial', 'oi', 'enviada', 'TEST-OUT-1');

6Disparar inbound

Do seu celular real, manda msg WhatsApp pro número da instance Evolution.

7Verificar

Logs backend:

webhook.processed workspace=1 provider=evolution
  summary={'inbound_processed': 1, 'inbound_skipped_no_lead': 0,
           'status_updates_processed': 0, 'lead_id': <ID>}

DB:

SELECT * FROM conversation_messages ORDER BY id DESC LIMIT 1;
SELECT id, status, responded_at FROM leads WHERE id = <lead_id>;
-- esperado: status='responded', responded_at preenchido

8Idempotência

Reenvia exatamente a mesma msg (Evolution às vezes faz retry).

SELECT COUNT(*) FROM conversation_messages
WHERE provider_message_id = '<EVO_MSG_ID>';
-- esperado: 1 (não duplica)

9Status update

Lê a msg do bot no celular. Evolution dispara messages.update com status READ.

SELECT read_at FROM outreach_messages
WHERE provider_message_id = 'TEST-OUT-1';
-- esperado: timestamp preenchido

Critério de sucesso

  • conversation_messages tem exatamente 1 linha pro provider_message_id
  • leads.status = responded + responded_at preenchido
  • conversations.unread_count = 1
  • Retry de webhook não duplica linha
  • outreach_messages.read_at preenchido após Evolution mandar messages.update
  • Nenhum 401/500 nos logs (exceto requests propositais sem HMAC)

Falhou? Debugging

SintomaCausa provável
401 invalid signature HMAC errado. Confere secret igual nos dois lados + Evolution assinando raw body (não JSON re-serializado)
401 com log reason=no_secret webhook_secret ausente em integration_settings.config, ou Fernet decrypt falhou (key rotation, ciphertext corrompido)
200 mas inbound_skipped_no_lead=1 Telefone do Lead não normaliza pro mesmo valor do remoteJid Evolution. Confere via normalize_phone_br()
200 mas Lead.status não muda link_outreach_reply respeitou status terminal (closed/won/lost/delivered/responded). Verifica status atual
Webhook nem chega no backend Evolution não está disparando. Confere config webhook na Evolution + ngrok ativo + endpoint correto
400 invalid json Evolution mandou body não-JSON. Aconteceu? Confere Content-Type

Rollback

Se smoke falhar e quiser desabilitar o webhook sem rollback de código:

UPDATE integration_settings
SET enabled = false
WHERE provider = 'evolution' AND workspace_id = 1;

Endpoint passa a retornar 401 (sem secret resolvido) — Evolution para de processar. Inbox volta a ficar cego.
